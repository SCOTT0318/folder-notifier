# 폴더 알림

Windows 11에서 지정한 폴더에 새 파일이 추가되면 화면 오른쪽 아래에 알림 팝업을 표시하는 데스크톱 앱입니다.

## 실행 방법

1. `dist/FolderNotifier-Setup.exe`를 실행하여 설치 (.NET 별도 설치 불필요)
2. 설치 완료 화면 또는 시작 메뉴의 **폴더 알림** 실행
3. **찾아보기**로 감시할 폴더 지정 (공유 폴더의 UNC 경로 직접 입력 가능)
4. 필요하면 **하위 폴더 포함** 선택
5. **감시 시작** 클릭
6. **미리보기**로 실제 파일 감지와 같은 팝업 표시 확인

설치 파일 하나에 앱과 런타임이 포함되어 있어 ZIP 압축 해제나 별도 런타임 설치가 필요 없습니다. 현재 사용자에게 설치되며, Windows **설정 → 앱 → 설치된 앱 → 폴더 알림**에서 제거합니다. 설정 파일은 업데이트 / 제거 시 유지합니다. 앱이 실행 중인 상태에서 업데이트하려면 트레이 메뉴의 **종료**로 먼저 종료하세요.

설치하지 않고 사용할 때는 `dist/FolderNotifier-1.6.0/FolderNotifier.exe`를 실행합니다.

**닫기(X)** 또는 **트레이로 숨기기**를 누르면 트레이에서 계속 실행됩니다. 트레이 아이콘을 두 번 클릭하면 창이 열립니다. 완전히 끝내려면 **종료** 또는 트레이 메뉴의 **종료**를 사용하세요.

**로그인 시 자동 실행**을 켜면 다음 Windows 로그인부터 트레이에서 실행하고 저장된 폴더 감시를 시작합니다. 이 옵션은 변경 즉시 적용되며, 끄면 자동 실행 등록을 삭제합니다. 저장된 폴더가 없으면 로그인 시 폴더를 선택할 수 있도록 창을 표시합니다.

**앱 실행 시 감시**는 사용자가 앱을 직접 실행했을 때 감시를 시작하는 별도 옵션입니다.

Windows 자동 실행은 현재 사용자 `HKCU/Software/Microsoft/Windows/CurrentVersion/Run`의 `FolderNotifier` 값에 실행 파일 경로와 `--startup`을 등록합니다. 앱 제거 시 해당 설치 경로를 가리키는 등록도 삭제합니다. 폴더 선택 등 사용자 설정은 유지합니다. Windows 시작 앱 설정에서 별도로 사용 안 함으로 지정한 경우에는 해당 설정에서도 다시 켜야 합니다.

## 동작 범위

- `FileSystemWatcher`의 생성 / 삭제 / 이름 변경 이벤트를 받으면 약 100ms 동안 몰리는 이벤트를 묶어 파일 목록을 비교합니다. 정상 감시는 고정 2초 조회를 기다리지 않습니다. 큰 폴더와 네트워크에서는 이벤트 전달 및 목록 확인 시간이 추가될 수 있습니다.
- 이벤트 누락 복구를 위해 30초마다 재확인합니다. 버퍼 초과 / 이벤트 연결 오류 시 감시기를 다시 연결하고 기존 기준 목록을 유지한 채 재확인합니다. 이벤트 감시를 연결하지 못하면 2초 간격으로 조회·재연결을 시도하며 화면에 해당 상태를 표시합니다.
- 감시 시작 후 최초로 성공한 조회의 기존 파일은 알림 대상에서 제외합니다.
- 파일 내용 수정과 삭제는 알리지 않습니다. 이름 변경은 새로운 경로로 간주하여 알립니다.
- 한 번에 여러 파일이 추가되면 알림 하나로 묶고 앱 이력에 파일별로 표시합니다.
- 하위 폴더의 숨김 파일을 포함하여 감시하며, 연결 지점과 심볼릭 링크는 순환 감시 방지를 위해 제외합니다.
- 공유 폴더의 연결 / 권한 오류는 화면과 이력에 표시하고 자동 재시도합니다. 실패한 조회는 기존 파일 목록을 덮어쓰지 않습니다.
- 조회 사이에 생겼다가 사라지는 파일은 감지하지 못할 수 있습니다. 알림은 파일 경로가 발견되었다는 의미이며 복사 완료를 보장하지 않습니다.
- 중지 중이거나 앱이 종료된 동안의 추가 파일은 다음 감시 시작 시 기존 파일로 처리합니다.
- 이력은 메모리에 최근 500행만 유지하며 앱 종료 시 사라집니다.
- 폴더와 옵션은 `%LOCALAPPDATA%/FolderNotifier/settings.json`에 저장합니다. 감시 대상 파일은 수정하지 않습니다.

**미리보기**는 실제 파일 감지와 동일한 독립 WPF 팝업을 표시하고 최근 활동에 미리보기 기록을 남깁니다. 팝업은 주 모니터 작업영역의 오른쪽 아래에 기본 8초 동안 표시되며, 마우스를 올리면 자동 닫힘을 멈추고 벗어나면 다시 8초를 셉니다. 새 알림은 기존 팝업의 내용과 표시 시간을 갱신합니다. **파일 목록 보기**는 앱 창을 복원하며 **✕** 또는 Escape는 팝업을 닫습니다. 표시 시 입력 포커스를 가져오지 않고 앱이 트레이에 숨겨져 있어도 표시됩니다. 앱 종료 / Windows 세션 종료 시 팝업도 정리합니다.

Windows 배너 알림 / 방해 금지 설정에 의존하지 않으며 Windows 알림 센터에는 저장되지 않습니다. 파일별 이력은 최근 활동에서 확인합니다. 잠금 화면이나 다른 Windows 세션에서의 표시는 지원하지 않습니다.

새 알림은 미확인 수를 누적합니다. 트레이 아이콘은 빨간 느낌표 배지로 바뀌며 툴팁에는 미확인 수가 표시됩니다. 앱 창이 작업표시줄에 있는 동안에는 WPF `TaskbarItemInfo.Overlay`에도 수량 배지를 표시합니다. 팝업 자동 닫힘 / ✕ / Escape / Alt+F4와 주기적 감시 상태 갱신은 미확인 표시를 지우지 않습니다. 앱 창을 열거나 다시 활성화하거나 **알림 확인**을 누르면 배지만 지웁니다. **비우기**는 배지와 이력을 함께 지웁니다. 새 파일은 파일 수, 테스트 / 오류는 발생 건수로 누적하며 트레이 숨김 안내는 포함하지 않습니다. 미확인 상태는 메모리에 유지하며 재실행 시 초기화됩니다.

## 파일명 알림과 화면 구성

감시 영역과 최근 활동은 왼쪽, 환경 설정은 오른쪽에 배치합니다. 900×600 창에서는 전체 화면 스크롤로 하단 조작부에 접근할 수 있으며 활동 목록은 별도로 스크롤합니다.

메인 화면 오른쪽 위에는 별도의 미확인 알림 카드가 있습니다. 새 알림은 카드의 배경 / 테두리 / 종 그래픽을 붉은색으로 바꾸고 수량 배지와 파일명 요약을 갱신합니다. 앱 복원 또는 알림 확인은 종을 기본 색으로 되돌리고 배지를 숨깁니다. 최근 알림은 확인 후에도 다시 열 수 있으며 다시 열기는 미확인 수를 추가하지 않습니다. 이력 비우기는 최근 알림도 초기화합니다. 트레이 숨김 안내는 이 카드의 최근 알림을 덮어쓰지 않습니다.

`NotificationArtwork`는 종과 파일 종류별 그림을 WPF `DrawingImage`로 생성합니다. 아이콘 글꼴이나 확장자 문자열에 의존하지 않는 벡터 그래픽이며 Windows 배율에서도 선명하게 표시됩니다. 알림 창의 큰 종 / 빨간 수량 배지와 PDF·스프레드시트·이미지·압축·일반 파일의 독립된 카드를 표시합니다. 종 흔들림은 유한한 도착 애니메이션이며 Windows의 클라이언트 영역 애니메이션 설정이 꺼져 있으면 생략합니다. 화면 하단에는 실제 어셈블리 버전을 표시합니다.

파일 알림은 `NotificationFile` 목록을 사용해 이름 / 확장자를 개별 행으로 렌더링합니다. 앞의 3개를 표시하고 초과 수량을 별도로 안내합니다. 이전의 메시지 전체 240자 제한을 제거했으며, 긴 이름은 최대 4줄로 줄바꿈·말줄임하고 전체 경로를 행의 툴팁으로 제공합니다. 목록 높이는 제한하여 열기 / 닫기 버튼이 화면 밖으로 밀리지 않게 합니다. 일반 안내와 오류는 파일 목록을 숨기고 본문을 표시합니다.

알림 미리보기는 예시 파일을 같은 렌더링 경로로 표시하며 실제 파일 생성 / 파일 수 증가는 없습니다. UI 검증은 200자가 넘는 한글 이름, 확장자 보존, 초과 수량, 단일 파일 / 일반 안내 전환, 작은 창과 버튼 접근을 검사합니다. 설치 DLL 수용 검증은 실제 추가된 파일 이름이 **표시 중인 목록**에 있는지 확인합니다.

## 개발 및 빌드

.NET 10 SDK와 Windows가 필요합니다. C# WPF와 .NET 내장 Fluent 테마 기반이며 알림은 독립 WPF 창, 트레이 아이콘은 Windows Forms NotifyIcon을 사용합니다. 외부 NuGet 라이브러리와 Python / Conda 의존성은 없습니다. 창은 작업영역에 맞춰 열리고, 작은 화면에서는 스크롤로 모든 조작부에 접근할 수 있습니다.

```powershell
dotnet run --project FolderNotifier.Tests -c Release -- .
dotnet build FolderNotifier.UiTests -c Release -m:1 -nr:false
dotnet run --project FolderNotifier.UiTests -c Release --no-build -- .
$installedDll = Join-Path $env:LOCALAPPDATA 'Programs\FolderNotifier\FolderNotifier.dll'
dotnet run --project FolderNotifier.AcceptanceTests -c Release -- $installedDll 'dist\tray-acceptance'
.\build.ps1
```

`FolderNotifier.AcceptanceTests`는 앱 프로젝트를 참조해 다시 빌드한 복사본 대신 지정한 설치 DLL을 그대로 로드합니다. 별도 설정과 고유한 임시 감시 폴더에서 실제 파일 3개를 생성한 뒤, 트레이 숨김 / native 팝업 표시 / 포커스 비탈취 / Windows Shell 아이콘 등록 / 팝업 자동 종료 후 미확인 유지 / 수량 누적 / 확인 후 해제를 검사합니다. 기존 설치 앱의 설정과 감시 폴더는 변경하지 않습니다. 테스트 파일은 종료 시 삭제하고, JSON 결과와 렌더링 미리보기만 증거 폴더에 남깁니다. 저장된 아이콘 PNG는 실행 앱이 선택한 아이콘이며 작업표시줄 화면을 캡처한 이미지가 아닙니다. Shell 아이콘 조회에는 .NET 10 WinForms의 내부 식별자를 사용하므로 런타임 구조가 바뀌면 검증 코드도 갱신해야 합니다.

기본 빌드 결과는 **.NET 10 Desktop Runtime (x64)**이 설치된 PC에서 실행합니다. 별도 .NET 설치 없이 배포하려면 다음 명령으로 자체 포함 빌드하세요. 최초 빌드 때 Microsoft 런타임 패키지 다운로드가 필요할 수 있습니다.

```powershell
.\build.ps1 -SelfContained
```

배포할 때는 `dist/FolderNotifier` 폴더 전체를 함께 전달하세요. 자체 포함 빌드는 `dist/FolderNotifier-1.6.0`처럼 앱 버전을 포함한 폴더에 생성되며 해당 폴더 전체를 전달합니다.

일반 빌드를 사용한다면 `dist/FolderNotifier/FolderNotifier.exe`를 실행합니다.

설치 EXE를 생성하려면 다음 명령을 사용합니다. 최초 실행 시 공식 Inno Setup portable 컴파일러를 프로젝트 안에 준비하고 SHA-256 및 게시자 서명을 확인합니다.

```powershell
.\build-installer.ps1
.\installer\verify-installer.ps1
```

생성 결과는 `dist/FolderNotifier-Setup.exe`입니다. 설치기는 한국어 UI, 시작 메뉴, 선택적 바탕 화면 바로가기, 제거 기능과 설치 완료 후 실행을 지원합니다. 앱 / 설치기는 코드 서명 인증서가 없는 빌드이므로 Windows에서 게시자 확인 경고가 표시될 수 있습니다.

## 앱 아이콘

투명 여백을 줄인 파란 폴더와 굵은 흰색 종 모양을 실행 파일, 창, 트레이에 적용합니다. 일반 / 미확인용 아이콘을 따로 생성하며 미확인 아이콘에는 빨간 느낌표 배지가 붙습니다. 두 ICO 모두 16 / 20 / 24 / 32 / 40 / 48 / 64 / 128 / 256px 프레임을 포함하고 트레이 크기에 맞는 프레임을 원본 ICO에서 직접 선택합니다.

작업표시줄은 앱 시작 시 지정하는 `FolderNotifier.Desktop` AppUserModelID와 동일한 ID를 가진 설치 바로가기로 연결합니다. 시작 메뉴 / 바탕 화면 바로가기와 설치 앱 목록에는 별도 배포 파일 `folder-notifier-v2.ico`를 지정하여 이전 EXE 아이콘 캐시와 구분합니다. 이 ICO도 배포 폴더에 함께 포함해야 합니다.

원본과 미리보기는 `FolderNotifier/Assets/`의 SVG / PNG / ICO 파일입니다. 아이콘을 다시 생성하려면 다음 명령을 실행한 뒤 앱을 빌드합니다.

```powershell
dotnet build tools/IconBuilder -c Release -m:1 -nr:false
dotnet run --project tools/IconBuilder -c Release --no-build -- FolderNotifier/Assets
```
